### Risks and how DB-1 handles each

| Risk | Decision |
|---|---|
| **Identity and sequences** | None exist: every key is a GUID. Nothing to reset after the copy. DB-1a still tests that the schema has 0 sequences, so this can't become wrong unnoticed. |
| **Supabase's public API** | Supabase serves its `public` schema over a REST API to anyone holding the project's public key. Tables there could expose password hashes. All tables go in a private schema `onlycars` (`HasDefaultSchema`, and the migrations history table with them), which that API does not serve, and this also protects future tables. |
| **Pooler** | **Session pooler, port 5432** (the key already verified), with `Maximum Pool Size=5` and `SSL Mode=Require`. One long-running process with a small pool is what session mode is for. Prepared statements, `SET LOCAL` and EF's migration lock all work. The transaction pooler (6543) is for many short-lived clients and drops session state. Supabase's direct host is not used because it needs IPv6 on this plan. |
| **GUID** | `uniqueidentifier` to `uuid`, same value. SQL Server and Postgres sort GUIDs differently, which only affects the last tie-break (`ThenBy(Id)`) between rows with identical timestamps. Accepted: these GUIDs are random, so that order never meant anything. |
| **Date and time** | `DateTimeOffset` to `timestamptz`, `DateOnly` to `date`. Npgsql refuses a non-zero offset, so the copy converts to UTC (same instant). Postgres keeps microseconds, SQL Server 100 ns, so copied values are truncated to the microsecond. Accepted: not visible anywhere. `UpdatedAt` is a concurrency token (never sent to the client), so a double save in one request must still match (`TireService.MoveAsync`); DB-1b tests it. |
| **Decimal** | `decimal(p,s)` to `numeric(p,s)` with the same precision and scale, exact. The risk is input with more decimals than the column, which may round differently: DB-1b pins today's result. |
| **Text comparison and sort** | SQL Server is case-insensitive and ignores trailing spaces; Postgres is exact. **Default for every string column:** a deterministic ICU collation `und`, so sort order is the same whatever Supabase's locale is (`a A b`, Hebrew in alphabetical order), and `lower()` and `LIKE` keep working. **`User.Email` and `Vehicle.Vin`:** a case-insensitive ICU collation (`und-u-ks-level2`, `deterministic: false`), because their equality and unique indexes are case-insensitive today (`AuthService.cs:53,112,235`, `VehicleService.cs:58,104,137`). This collation can't go on searched columns, since Postgres 17 has no `LIKE` on it. Neither column is searched. Since DB-1b, search is a parameterised regular expression (`TextRules.SearchPattern`), which matches final Hebrew letters and looks through invisible marks as SQL Server did. |
| **NUL characters** | Postgres text can't hold `\u0000`; SQL Server can. After the move, such a request would be a 500, so it must become a 400. The copy stops and lists the row ids if any stored value contains one. |
| **Database errors** | Deadlock and lock errors change from numbers to SQLSTATE (`40P01`, `55P03`). The old check would silently never match, because it reads `Number` by reflection. ### DB-1c (backend): the copy tool, rehearsed locally (signed off 2026-11-07)

**Goal:** one command copies every row from SQL Server to Postgres and proves that the copy is identical, and it has been run on a real local database first.

**Scope (Backend, `backend-engineer`):** a console project `tools/OnlyCars.DbCopy`, outside `src/`, so SQL Server stays out of the Docker image. Added to `OnlyCars.slnx`.
- **Default is a dry run**, like `sweep-orphans`: it reads the source and writes nothing. Only `--write` writes.
- **Connections:** from the user-secrets of `src/OnlyCars.Api` (same `UserSecretsId`), `ConnectionStrings:AzureSource` and `ConnectionStrings:SupabaseApp`, or a local pair for the rehearsal given by name. It prints database and host names, never a password, never row contents.
- **Source:** only `SELECT`s, with the reads retried on 40613 for up to 2 minutes while Azure wakes. It stops unless the last row of `__EFMigrationsHistory` is `20261106063910_TemplateHebrewNames` and each model table and column exists in the source. It reports the `Legacy_*` tables with their row counts and does not copy them (decisions.md 2026-11-06, Honda tires dropped, L222).
- **Dry-run report:** row count and size per table, values with `\u0000`, the ids of `User.Email` and `Vehicle.Vin` values with trailing spaces and their count per column, and pairs that would collide under the new Email and VIN collation after trimming (ids only). It also reports the source's database collation and any string column with a different one, and connects to the target and reports whether it is empty, without writing.
- **Trailing spaces in Email and VIN (decisions.md "DB-1b sign-off"):** the only change the copy makes to a value. The app's converter doesn't touch a stored value on reading, so a stored `'X '` would be missed by its trimmed check and could sit beside `x` in the unique index. `--write` removes trailing U+0020 from these two columns only, the same as `TrimEnd(' ')` in the converter; tabs and leading spaces stay, and every other column is copied exactly. It reports the count and ids. A collision after trimming (`User.Email` across all users, `Vehicle.Vin` per `UserId`, including two blank VINs) stops `--write` before it writes anything, and the owner decides.
- **Write:** all in one Postgres transaction, so a failure leaves nothing. Target tables must be empty, except the seeded `TaskTemplates`, which are deleted first so the source's rows win. Tables go in foreign-key order from the EF model, using batched parameterised `INSERT`s, not `COPY`: the data is small, and this needs nothing special from the pooler. A nullable foreign-key cycle, if the model has one, is filled in a second pass.
- **Verify, inside the transaction and before commit, and again by `--verify` alone:** row count per table, then a hash per row by primary key over every column, in canonical form (GUID lower case; timestamps UTC truncated to the microsecond; decimals invariant at column scale; strings as exact UTF-8, except that `User.Email` and `Vehicle.Vin` have their trailing spaces removed on the source side only, so a target value that kept them fails). Any difference rolls back and lists table and id.
